# Видеокарта. RTX 4060 8 ГБ

Константинов Валерий

Цифры ниже — паспорт обычной настольной RTX 4060 (не Ti и не ноутбук): 8 ГБ GDDR6, шина 128 бит, 3072 CUDA-ядра, TGP 115 Вт.

## Часть 1. Теория

### 1. Пять основных блоков

| Блок | Зачем |
|---|---|
| GPU | Считает кадр: вершины, пиксели, свет. На 4060 это 3072 CUDA-ядра плюс RT- и тензорные ядра |
| VRAM | Хранит то, что GPU читает постоянно: текстуры, модели, буфер кадра |
| Шина памяти | Канал между GPU и VRAM. У 4060 ширина 128 бит |
| Подсистема питания | Делает из 12 В стабильные напряжения ядра и памяти и отдаёт нужный ток |
| Охлаждение | Забирает тепло, в которое превращаются эти ватты |

PCI-E и HDMI/DisplayPort — не вычислительные блоки, а вход и выход. Они на схеме.

### 2. Чем GPU отличается от CPU

1. **Мало сложных ядер против тысяч простых.** CPU — несколько больших ядер с предсказанием переходов. Ему выгодны ветвления: ОС, логика игры, физика «что произошло». GPU — тысячи одинаковых ALU. Ему выгодна одна операция сразу над кучей данных: пиксели, матрицы.
2. **Задержка против потока.** CPU оптимизирован, чтобы одна задача быстро дошла до ответа. GPU оптимизирован, чтобы пропустить много данных в секунду, даже если один поток ждёт память. Поэтому кадр и нейросеть считают на GPU, а решение «что рисовать» принимает CPU.

### 3. VRAM и оперативная память

VRAM стоит на самой плате и соединена с GPU широкой шиной. Оперативная память обслуживает CPU. GPU может читать её только через PCI-E, а это узкое место.

Видеопамять делают быстрой, потому что ядра простаивают, если данные не успевают. У 4060 шина даёт **272 ГБ/с**. Двухканальная DDR5 обычно в районе 70–90 ГБ/с и ещё не подключена к GPU напрямую. Для текстур и буфера кадра этого мало.

### 4. SIMT и варпы

SIMT значит: одна инструкция выполняется сразу многими потоками. На NVIDIA потоки собраны в варп по 32. Блок управления читает команду один раз и отдаёт её всем 32, поэтому не нужен отдельный планировщик на каждый поток.

Пока часть варпа ждёт память, GPU переключается на другой варп. Так шина не простаивает. Если потоки внутри варпа расходятся по `if/else`, обе ветки всё равно выполняются по очереди, лишние потоки маскируются. Поэтому на GPU выгодны одинаковые операции, а не запутанная логика.

### 5. Питание и охлаждение

Питание держит напряжение, когда нагрузка скачет от кадра к кадру. Охлаждение уносит те же ватты в виде тепла. У этой карты лимит **115 Вт**, потолок температуры GPU — **90 °C**.

Если кулер не справляется, карта сначала сбрасывает частоты (троттлинг), кадр начинает проседать. Дальше срабатывает защита и GPU отключается, чтобы не сгореть. Долго жить на пределе температуры ему тоже вредно.

## Часть 2. Схема

Путь кадра — одна горизонталь слева направо. Память снизу от GPU, питание сверху. Линии не пересекаются.

```text
                              ┌────────────────┐
                              │ Подсистема     │
                              │ питания (VRM)  │
                              │   питание 12 В │
                              └───────┬────────┘
                                      │
                                      ▼
┌──────────┐   PCI-E 4.0 x8   ┌───────────────┐    кадр     ┌────────────┐      ┌──────────┐
│          │  ───────────────►│               │ ───────────►│            │─────►│          │
│   CPU    │   команды кадра  │      GPU      │             │  HDMI / DP │      │ Монитор  │
│          │                  │   3072 CUDA   │             │            │      │          │
└──────────┘                  └───────▲───────┘             └────────────┘      └──────────┘
                                      │
                                      │ шина памяти, 128 бит
                                      │
                              ┌───────┴────────┐
                              │   VRAM, 8 ГБ   │
                              │     GDDR6      │
                              └────────────────┘

                              ┌────────────────┐
                              │  Охлаждение    │
                              │ тепло с GPU    │
                              │ и с микросхем  │
                              │ памяти         │
                              └────────────────┘
```

БП отдаёт 12 В в VRM. Слот PCI-E даёт до 75 Вт, а лимит карты 115 Вт, поэтому у стандартной 4060 есть ещё один разъём питания, обычно 8-pin. VRM кормит GPU и VRAM. Кулер сидит на чипе и на микросхемах памяти и в путь кадра не входит.

## Часть 3. Практика

Карта: **GeForce RTX 4060 8 ГБ**, референсные характеристики NVIDIA.

| Параметр | Значение |
|---|---|
| VRAM | 8 ГБ |
| Тип памяти | GDDR6 |
| Шина | 128 бит |
| CUDA-ядра | 3072 |
| TGP (то, что в быту называют TDP платы) | 115 Вт |
| Эффективная скорость памяти | 17 Гбит/с = 17 000 МГц |

### Пропускная способность

В формуле берётся эффективная частота, та самая, что в GPU-Z выглядит как 17 000 МГц. Реальная частота кристалла памяти ниже, у GDDR6 за такт проходит несколько передач.

```text
17 000 МГц × 128 бит / 8 = 272 000 МБ/с = 272 ГБ/с
```

Паспорт NVIDIA и спецификации плат: **272 ГБ/с**. Расчёт с паспортом совпал.

### От кнопки «Играть» до картинки

1. CPU загружает игру с диска в оперативную память и запускает процесс.
2. CPU считает логику кадра и через DirectX или Vulkan собирает команды: что рисовать и какими ресурсами.
3. Драйвер отправляет этот буфер команд по PCI-E на GPU.
4. Текстуры и сетки, которых ещё нет на карте, переписываются в VRAM. Дальше GPU читает их по своей шине, а не из оперативной памяти.
5. GPU гоняет шейдеры параллельно и записывает готовый кадр в буфер, который тоже лежит в VRAM.
6. Блок вывода забирает этот буфер и шлёт пиксели по HDMI или DisplayPort на монитор.
7. Следующий кадр начинается снова с шага 2. CPU не рисует пиксели, он только готовит работу.

## Часть 4. Вывод

Игры и нейросети устроены одинаково с точки зрения железа: одна и та же операция над огромным массивом чисел. У GPU тысячи ядер и широкая память, поэтому матричные умножения он делает пакетом, а не по одному числу, как CPU.

Обучение и запуск модели — это как раз такой поток, а не длинная цепочка разных решений. Поэтому видеокарта, которую делали под пиксели, оказалась подходящим вычислителем для ИИ. CPU при этом остаётся нужен: он запускает программу, готовит батч и кормит GPU данными.
